## 3. ระบบเดินเงิน (สรุป)

แนวคิด: ทุกไม้ที่แพ้สะสมเป็น **หนี้** (`deficit = ยอดตอนเริ่มรอบ − ยอดปัจจุบัน`) แล้วไม้ถัดไปเดิมพันจากหนี้จริง ไม่ใช่คูณคงที่

**ลำดับความสำคัญของสูตร (จากบนลงล่าง ตัวแรกที่ตรงถูกใช้):**

| ลำดับ | เงื่อนไข | สูตร | ผลเมื่อชนะ |
|---|---|---|---|
| 1 | ไม้ 1 | `base` | +1 ฐาน |
| 2 | ไม้ ≥3 และ **Close-All** (ชนะแล้วแพ้) | `deficit + base` | **ปิดหนี้ 100% → คืนทุน** |
| 3 | **Hit 2** (ชนะไม้ก่อนมาแล้ว) | `deficit + base` | **ปิดหนี้ 100% → คืนทุน** |
| 4 | อื่น ๆ ที่เหลือ (รวม **ไม้ 2** แม้มีธง Close-All) | `deficit/2 + base` | ปลดหนี้ ~50% |

> **build 206:** Close-All มีผลตั้งแต่ **ไม้ 3** — ไม้ 2 ใช้ครึ่งหนี้ (1.5× ฐาน) เพราะชนะแล้วได้กำไร 1.5 ฐาน > หนี้ 1 ฐาน จึงคืนทุนครบอยู่แล้ว
> ผลวัดจริง: ไม้ 2 ลดเงินที่ใช้ **25%** ในเคส Close-All (89% ของไม้ 2 ทั้งหมด) → ภาพรวมไม้ 2 ลด **18.3%**

**บันไดแพ้ติด (base = 0.00012, build 206):**
`0.00012 → 0.00018 → 0.00027 → 0.000405 → 0.0006075 → 0.00091125 → 0.00136688 → 0.00205031 → …`

| แพ้ติด | ใช้เงินรวม (206) | ก่อน 206 |
|---|---|---|
| 5 ไม้ | 0.00158 | 0.00179 |
| 10 ไม้ | 0.01360 | 0.01514 |
| 15 ไม้ | 0.1050 | 0.1170 |
| 20 ไม้ | **0.7997** | 0.8907 |

**ลำดับ ชนะ–แพ้–ชนะ:** ไม้ 3 (หรือไม้ 2 ที่มีธง Close-All) ใช้ยอด "หนี้เต็ม/ครึ่งหนี้ + ฐาน" → ชนะแล้วคืนทุน + กำไร

**กฎรีเซ็ต**
- ชนะติด 2 **และ** ยอด ≥ จุดเริ่มรอบ → รีเซ็ตไม้ 1 (`2-WIN RECOVERED`)
- ชนะติด 2 แต่ยังไม่ถึงทุน → ไม่รีเซ็ต (`2-WIN SHORT`)
- ชนะไม้ตื้นตาเดียว / รอบทบคืนทุนครบ 100% → รีเซ็ตไม้ 1 (`RECOVERED`)
- ชนะที่ไม้ 1 แต่หนี้ยังเหลือ → **ไม่รีเซ็ตรอบ** เล่นไม้ 2 ต่อ (`DEBT-NOT-CLEARED` กันหนี้หายเกลี้ยง)
- แพ้ → ไม้ +1 (สูงสุด 20) · เงินไม่พอ → รีเซ็ตไม้ 1 หรือหยุด

### 7.1 บล็อก `session` — อ่านผลทั้งเซสชัน (build 200)

`summary` คิดจากบัฟเฟอร์ 1,500 event สุดท้าย → เซสชันยาวจะเห็นแค่ช่วงท้าย **ให้อ่าน `session` แทน**

```json
"session": { "bets": 2073, "realBets": 1835, "virtualBets": 239,
             "wins": 922, "losses": 913, "net": 0.13753592,
             "maxStep": 15, "minutes": 20, "bufferBets": 204,
             "maxDrawdown": 0.04123456, "maxDrawdownPct": 1.11, "peakBalance": 3.89639566,
             "truncated": true, "perfResumed": false }
```

| field | ความหมาย |
|---|---|
| `bets` / `realBets` / `virtualBets` | ไม้ทั้งหมด / ไม้เงินจริง / ไม้ 0$ |
| `wins` / `losses` | นับจากไม้จริงเท่านั้น → % ชนะควรใกล้ 49.5% |
| `net` | **P/L จริงทั้งเซสชัน** (ไม่ถูกตัดทอน) |
| `maxStep` | ไม้ลึกสุดที่ไปถึง |
| `maxDrawdown` | **DD สูงสุดของเซสชัน ($)** — ยอดพีคที่เคยสูงสุด ลบด้วยยอดต่ำสุดหลังพีคนั้น (build 207) |
| `maxDrawdownPct` | DD คิดเป็น % ของยอดพีค |
| `peakBalance` | ยอดเงินสูงสุดที่เห็นระหว่างเซสชัน (ใช้เป็นฐานเทียบ DD) |
| `truncated` | `true` = ไฟล์ถูกตัด (ล็อกแค่ท้ายเซสชัน) — ปกติ |
| `perfResumed` | `true` = เซสชันนี้ต่อจากแท็บที่รีเฟรช (PERF ไม่ได้เริ่มที่ 0) |

> **DD นับเฉพาะไม้เงินจริง** (อัปเดตทุกลูกที่จบผล) · รีเซ็ตเมื่อเริ่มเซสชันใหม่ · ถ้า resume หลังรีเฟรชจะกู้ค่าที่บันทึกไว้ใน `savedRecovery` ต่อจากเดิม

### `verify.cjs` ตรวจอะไรบ้าง

**โค้ด:** มี `BUILD_NO` · title/manifest ตรง build · ค่าคงที่โหมดลม · guard ฝั่ง · watchdog · `perfReset` ครบ 3 เส้นทาง · mini timer · auto-mini · static checks ของสูตรเงิน

**diag:**
| ตรวจ | เกณฑ์ |
|---|---|
| build ใน diag ตรงกับโค้ด | WARN ถ้าไม่ตรง (แค่เตือน) |
| ERROR / HANG | ต้อง 0 |
| `ZERO_STALL` | ควร 0 |
| คลิกซ้ำไม้ 0$ | ≤ 3 ครั้ง/ไม้ |
| ไม้ 0$ ได้ทอยจริง | ≥ 75% (ปกติ 100%) |
| `avgPrep` | < 100 ms |
| `perf.bets` vs จำนวนรอบจริง | ต่าง ≤ 1 (รอยต่อ start/stop) |
| `avgWait` ไม้ 0$ | ≤ 1,000 ms |
| **สูตรยอดเดิมพันจาก ledger** | ต้องตรง 100% |
| `summary.gaps` | 0 |
| **DD (`session.maxDrawdown`)** | ≥ 0 และ ≤ `peakBalance` · รายงานเป็น $ และ % (build 207) |
| จำนวนไม้ทั้งเซสชัน | เทียบ `session.bets` + บอกว่า diag ถูกตัด |

**ตัวตรวจสูตรเงิน (build 205-206):** เดิน state machine ย้อนจาก `bets[]` (ยอดฐาน → หนี้ → streak → Close-All → step) คำนวณยอดที่ "ควรเป็น" ของทุกไม้ แล้วเทียบยอดจริง (tolerance ขึ้นกับขนาดยอด) พร้อมสรุป:

```
✔ ยอดเดิมพันตรงสูตร K=2 · ตรวจ 121 ไม้ · ตรง 121 · ไม่ตรง 0
ℹ ไม้ 2: เต็มหนี้ 18 ครั้ง (Hit 2 ชนะไม้ 1 มาแล้ว 18 · Close-All 0) · ครึ่งหนี้ 34 ครั้ง
```

- เลือกกฎตาม build ของ diag: **≥206** = ไม้ 2 ยกเว้น Close-All · **ก่อน 206** = Close-All ถึงไม้ 2
- ถ้า diag เป็น build ≥206 แล้วยังเจอ Close-All เต็มหนี้ที่ไม้ 2 → **FAIL ทันที**

| ไม้ 0$ ค้าง | `ZERO_STALL`, `HANG` | ปล่อยให้ระบบข้าม (ไม่เสียเงิน) |
| เงินไม่พอ | `BALANCE_RESET` | ปกติ; ถ้าหยุดให้เติมเงิน/ลดยอดฐาน |
| ปุ่มเดิมพันกดไม่ติด | `START_BLOCK`, `NOBET_PROBE`, `REAL_AMOUNT_GUARD` | กด `🧪 SELF-TEST`, ตรวจว่าอยู่หน้า Dice |
| HUD ไม่ขึ้น | ต้องอยู่โดเมน stake.com | เปิดหน้าเกมใหม่ / Reload |
| ชนะติด 2 ไม่รีเซ็ต | `TWO_WIN_SHORT` | ถูกต้อง — รอจนยอดถึงทุนจริง |
| ไม้ 2 ใช้ยอดไม่เท่าที่คิด | `verify` บรรทัด "ไม้ 2:" | ถ้า build ≥206 ต้องเป็นครึ่งหนี้; ถ้าเป็น Hit 2 เต็มหนี้ถูกต้อง |
| แท็บเก่าค้าง | title แท็บ (`STAKE_RUN` / `STAKE_IDLE`) | เก็บกวาดเองทุกครั้งที่เริ่มเซสชัน (ข้อ 9.1) |

### 9.1 การปิดแท็บ / เก็บกวาดแท็บค้าง (build 188)

ทุกครั้งที่เริ่มเซสชันใหม่ แท็บใหม่จะสั่ง `CLOSE_STALE_TABS` → `background.js` เก็บกวาดแท็บ Stake อื่น:

| สถานะแท็บ | ธง `window.__stakeBotState.running` | ผล |
|---|---|---|
| title `STAKE_DONE` / `STAKE_IDLE` | ไม่ต้องอ่าน | ปิดทันที |
| title `STAKE_RUN` | `true` (กำลังแทง) | **ข้าม — ไม่แตะ** |
| title `STAKE_RUN` | `false` (หยุดแล้ว) | ปิดทันที |
| title `STAKE_RUN` | ไม่มีธง (build เก่า) | เฝ้า title 12 วิ — นิ่งสนิทจึงปิด |
| title `STAKE_HOLD` | — | **ข้าม — ไม่แตะ** |

- หยุดแบบไม่ปิดแท็บ title เปลี่ยนเป็น `STAKE_IDLE|R=…|P=…` ทันที
- ถ้าไม่แน่ใจ ให้ปิดแท็บเก่าด้วยมือก่อน Reload

**เก็บหลักฐาน:** เกิดอาการ → `Alt+D` → ส่งไฟล์ + เวลา/เลขไม้

## 11. ข้อจำกัด / ความเสี่ยง

- **RTP 99% → EV ติดลบ ~1% ของยอดเดิมพันระยะยาว** ไม่มีการรับประกันกำไร; ผล 200 นาทีที่ +1.51 เป็นผลช่วงสั้น
- ไม่มีตัดขาดทุน/เป้ากำไร — หยุดเมื่อ: **ครบเวลาและยอดกลับเป็นบวกที่ไม้ 1**, เงินหมด, ตรวจฝั่งไม่ได้
- **ด่านเข้าแทงลม (build 213):** แพ้จริงติด **3** ตา → แทงลม **3 ตา (ตาที่ 4–6)** → **ออกลมทันทีที่ตาที่ 6 ไม่ว่าชนะหรือแพ้ → กลับไปแทงเงินจริง (K2) ที่ไม้เดิม** · **จากนั้นไม่เข้าแทงลมอีก** จนกว่าจะ **ชนะจริงติด 2** (หรือจบรอบกลับไม้ 1) → รีเซ็ต → เริ่มนับ 3 ใหม่
- **พยุงหลังครบเวลาได้ไม่เกิน 60 นาที** (`SESSION_RECOVERY_MAX_EXTRA_MIN`, build 208): เดิมค่านี้ประกาศไว้แต่ไม่ถูกอ้างอิงที่ไหนเลย → เซสชันวิ่งค้างไม่จำกัด (เคสจริง 18 พ.ย.: 37 นาที, −6.317$)
- **ตา Close-All (ไม้ ≥3) ยังใช้ยอดเต็มหนี้** เพื่อให้ W-L-W คืนทุน — ถ้าแพ้ หนี้โตขึ้นหนึ่งก้าว
- ไม้ 2 ใช้ครึ่งหนี้: ถ้าแพ้ หนี้สะสมเร็วขึ้นเล็กน้อยในก้าวนั้น แต่ยอดที่เสี่ยงน้อยลง 25%
- ชนะติด 20 ไม้มีโอกาส ~1 ใน 840,000 แต่ยังเกิดขึ้นได้ · maxStep 15 เคยเกิดจริงในเซสชัน 20 นาที
- **ผลจำลอง (พอร์ต 3.44$, p=49.5%, build 199 ที่ไม้ ≥2 ครึ่งหนี้ทุกไม้):** แตะ 0 ~4.6% · DD p95 ~76% · ผลตอบแทนมัธยฐาน +3.3%/รอบ — build 206 ใกล้เคียง (ไม้ 2 เบาลงอีก 25% ในเคส Close-All)
- diag ไม่ได้บันทึก drawdown ต่อเซสชัน — ถ้าต้องการตัวเลข DD ให้เพิ่มตัวนับในบล็อก `session`
- `data-testid` ของเว็บอาจเปลี่ยน → ดู `SIDE_CONTROL_MISS.dom` ใน diag
